# Qwen Powerups

Скиллы для **[Qwen Code](https://github.com/QwenLM/qwen-code)**. Сейчас в репозитории один скилл — **Senior Advisor**: он позволяет Qwen обратиться к внешней модели за независимым вторым мнением, когда задача требует дополнительной проверки.

## Senior Advisor

Qwen ведёт задачу: исследует код, принимает решения, вносит изменения и запускает тесты. Если возникает сложный вопрос, он может посоветоваться с Codex, Claude Code, Grok, Kimi или Z.AI.

Консультация устроена так:

1. Qwen выделяет один технический вопрос и готовит короткий пакет с фактами, ограничениями и минимальным примером.
2. Python-скрипт проверяет формат, размер пакета и признаки секретов.
3. Выбранный провайдер получает подготовленный вопрос. CLI запускается во временной рабочей директории с ограничениями, предусмотренными его адаптером.
4. Qwen проверяет рекомендации по коду, тестам и документации, объясняет, что принимает или отклоняет, и продолжает работу.

По инструкции скилла в пакет не должны попадать история диалога, названия внутренних проектов и посторонние файлы. Ответ консультанта остаётся мнением, которое нужно проверить.

## Требования

- Qwen Code с поддержкой Agent Skills.
- Python 3; проверенная среда — Python 3.12. Сторонние Python-пакеты не нужны.
- Хотя бы один установленный и авторизованный CLI провайдера либо ключ Z.AI.

## Установка в Qwen Code

Для всех ваших проектов, в macOS или Linux:

```sh
git clone https://github.com/miolamio/qwen-powerups.git
cd qwen-powerups
mkdir -p ~/.qwen/skills/senior-advisor
cp -R senior-advisor/. ~/.qwen/skills/senior-advisor/
```

Для установки только в один проект скопируйте `senior-advisor/` в `<проект>/.qwen/skills/`. Оба расположения поддерживаются [механизмом Agent Skills в Qwen Code](https://qwenlm.github.io/qwen-code-docs/en/users/features/skills/).

Откройте `/skills` в Qwen Code и убедитесь, что `senior-advisor` есть в списке и включён. Если он не появился, перезапустите Qwen Code.

Проверьте наличие провайдеров:

```sh
python3 ~/.qwen/skills/senior-advisor/scripts/ask_senior.py --doctor
```

Эта команда проверяет наличие CLI в `PATH` или переменной `ZAI_API_KEY`. Она не делает запросов к моделям и не проверяет авторизацию.

## Использование

В диалоге с Qwen Code попросите:

```text
Позови сеньора: проверь, не приведёт ли этот план миграции к потере данных.
```

```text
Спроси у сеньора, почему тест продолжает падать после двух разных исправлений.
```

Или вызовите скилл напрямую:

```text
/senior-advisor
```

Скилл также разрешает Qwen самому запросить консультацию при высоком риске, после двух разных неудачных подходов или при важном допущении, которое нельзя проверить локально. Перед обращением Qwen должен назвать провайдера и причину вызова, предупредить о передаче фрагмента задачи и расходе квоты. Лимит — три самостоятельные консультации за сессию; дальнейшие требуют согласования.

## Провайдеры и настройки

| Значение `SENIOR_PROVIDER` | Подключение |
| --- | --- |
| `codex` | Установленный и авторизованный Codex CLI |
| `claude` | Установленный и авторизованный Claude Code |
| `grok` | Установленный и авторизованный Grok CLI |
| `kimi` | Установленный и авторизованный Kimi Code |
| `zai` | HTTP API, ключ в `ZAI_API_KEY` |

По умолчанию используется `auto`: первый доступный провайдер в порядке `codex,claude,grok,kimi,zai`. Доступность определяется так же, как в `--doctor`. После ошибки запроса автоматического перехода к другому провайдеру нет.

Чтобы выбрать провайдера явно, задайте переменные перед запуском Qwen:

```sh
export SENIOR_PROVIDER=claude
export SENIOR_TIMEOUT_SECONDS=300
qwen
```

Модель можно задать через `SENIOR_<PROVIDER>_MODEL`, например `SENIOR_CLAUDE_MODEL`. При прямом вызове скрипта параметр `--model` имеет приоритет над переменной окружения. Без переопределения CLI использует свою модель по умолчанию.

Команды установки, авторизация, настройка моделей и отдельного окружения для Codex описаны в [справочнике провайдеров](senior-advisor/references/providers.md).

## Формат вопроса и локальная проверка

Обычно пакет составляет сам Qwen. Проверить формат вручную можно без обращения к модели:

```sh
python3 senior-advisor/scripts/ask_senior.py --lint <<'PACKET'
Question: How should push isolate default lists while preserving explicit-list mutation?
Stack: Python 3.12.1, standard library
Given: push(item, bucket=[]) appends item and returns bucket; default calls share a list.
Constraints: Preserve mutation and identity of an explicitly supplied list.
Ruled out: none
Evidence:
def push(item, bucket=[]):
    bucket.append(item)
    return bucket
PACKET
```

Все шесть заголовков обязательны. Лимиты: 1200 байт до `Evidence:`, 100 строк для секции `Evidence:` вместе с заголовком и 8192 байта на весь пакет. `--lint` возвращает JSON с результатом проверки; код выхода `0` означает успех, `2` — ошибку.

Подробные правила находятся в [SKILL.md](senior-advisor/SKILL.md), примеры сокращения вопросов — в [packet-examples.md](senior-advisor/references/packet-examples.md).

## Передача данных и статус проверки

Подготовленный пакет отправляется внешнему провайдеру и расходует его квоту или оплачивается по условиям вашего аккаунта. Перед отправкой нужно убрать секреты, персональные данные и внутренние адреса: автоматическая проверка по шаблонам не гарантирует обнаружение всех чувствительных данных. Агенту запрещено обходить проверки через `--allow-sensitive` или `--allow-narrative`.

По зафиксированным в репозитории проверкам от 8 сентября 2026 года, консультации через Codex и Claude Code прошли полный цикл на macOS. Адаптеры Grok, Kimi и Z.AI реализованы, но полный цикл для них не проверен.

## Обновление

Из директории клона выполните:

```sh
git pull --ff-only
cp -R senior-advisor/. ~/.qwen/skills/senior-advisor/
```

Установленный скилл — отдельная копия. Сам по себе `git pull` её не обновляет; повторное копирование перезапишет локальные правки в совпадающих файлах.

## Разработка

```text
senior-advisor/
├── SKILL.md                     # Инструкции для Qwen
├── scripts/
│   ├── ask_senior.py             # Проверка пакетов и вызовы провайдеров
│   └── test_ask_senior.py        # Офлайн-тесты
└── references/
    ├── providers.md             # Подключение провайдеров
    └── packet-examples.md       # Примеры подготовки вопросов
```

Запуск тестов из корня репозитория:

```sh
python3 -B -m unittest discover -s senior-advisor/scripts -p 'test_*.py'
```

Тесты используют стандартный `unittest`, изолируют переменные окружения и блокируют реальные сетевые запросы и запуск CLI провайдеров. Правила для участников — в [AGENTS.md](AGENTS.md).
