# Qwen Powerups

Скиллы для **[Qwen Code](https://github.com/QwenLM/qwen-code)**. Сейчас в репозитории один скилл — **Senior Advisor**: он позволяет Qwen запросить у внешней модели второе мнение или план сложной задачи. Частоту обращений задаёт пользователь; скрипт проверяет лимиты и ведёт журнал консультаций.

## Senior Advisor

Qwen ведёт задачу: исследует код, принимает решения, вносит изменения и запускает тесты. Если возникает сложный вопрос, он может посоветоваться с Codex, Claude Code, Grok, Kimi или Z.AI.

Консультация устроена так:

1. Qwen готовит пакет для совета (`advice`) или плана (`plan`), сохраняя факты, ограничения и критерии результата.
2. Python-скрипт проверяет пакет, признаки секретов, основание для обращения, доступный бюджет и историю консультаций.
3. Выбранный провайдер получает подготовленный вопрос. CLI запускается во временной рабочей директории с ограничениями, предусмотренными его адаптером.
4. Пакет и ответ сохраняются в локальный журнал. Ошибки провайдера тоже записываются.
5. Qwen проверяет рекомендации по коду, тестам и документации, объясняет, что принимает или отклоняет, и продолжает работу. При выполнении плана он проверяет результат каждого шага перед переходом к следующему.

По инструкции скилла в пакет не должны попадать история диалога, названия внутренних проектов и посторонние файлы. Ответ консультанта остаётся мнением, которое нужно проверить.

## Требования

- Qwen Code с поддержкой Agent Skills.
- Python 3; проверенная среда — Python 3.12. Сторонние Python-пакеты не нужны.
- Хотя бы один установленный и авторизованный CLI провайдера либо ключ Z.AI.

## Установка в Qwen Code

Для всех ваших проектов, в macOS или Linux:

```sh
git clone https://github.com/miolamio/qwen-powerups.git
cd qwen-powerups
mkdir -p ~/.qwen/skills/senior-advisor
cp -R senior-advisor/. ~/.qwen/skills/senior-advisor/
```

Для установки только в один проект скопируйте `senior-advisor/` в `<проект>/.qwen/skills/`. Оба расположения поддерживаются [механизмом Agent Skills в Qwen Code](https://qwenlm.github.io/qwen-code-docs/en/users/features/skills/).

Откройте `/skills` в Qwen Code и убедитесь, что `senior-advisor` есть в списке и включён. Если он не появился, перезапустите Qwen Code.

Проверьте наличие провайдеров:

```sh
python3 ~/.qwen/skills/senior-advisor/scripts/ask_senior.py --doctor
```

Эта команда проверяет наличие CLI в `PATH` или переменной `ZAI_API_KEY`. Она не делает запросов к моделям и не проверяет авторизацию.

## Использование

В диалоге с Qwen Code попросите:

```text
Позови сеньора: проверь, не приведёт ли этот план миграции к потере данных.
```

```text
Спроси у сеньора, почему тест продолжает падать после двух разных исправлений.
```

```text
Попроси сеньора составить план переноса очереди: с проверкой каждого шага и откатом.
```

Или вызовите скилл напрямую:

```text
/senior-advisor
```

Qwen также может обращаться самостоятельно в пределах выбранной политики. Для каждого вызова он указывает причину через `--trigger`:

| Причина | Когда применяется |
| --- | --- |
| `user` | Пользователь попросил консультацию в текущем сообщении |
| `stakes` | Решение необратимо или может затронуть значительную часть системы |
| `failure` | Два разных подхода уже завершились неудачей |
| `assumption` | Важное допущение нельзя проверить локально |
| `confusion` | Агент запутался, противоречит себе или не может выбрать подход |
| `planning` | Нужен порядок выполнения сложной задачи |

Перед обращением Qwen должен назвать провайдера, причину и сообщить о передаче фрагмента внешнему сервису. При затруднении инструкция требует запросить консультацию с `confusion`. Если бюджет исчерпан, агент должен остановиться и обратиться к пользователю.

## Частота консультаций

По умолчанию действует политика `normal`. Её параметры и другие встроенные варианты:

| Политика | Самостоятельные обращения | Бюджет | Из него для `confusion` | Интервал |
| --- | --- | ---: | ---: | ---: |
| `off` | Запрещены | 0 | 0 | 0 с |
| `rare` | Только `stakes` и `confusion` | 2 | 1 | 300 с |
| `normal` | Все пять самостоятельных причин | 5 | 1 | 60 с |
| `eager` | Все пять самостоятельных причин | 12 | 2 | 0 с |

Бюджет учитывает записанные самостоятельные попытки, включая ошибки провайдера. Он общий для сессий в одной папке журналов: по умолчанию учитывается вся история сессий, активных в последние 240 минут. Создание новой сессии не сбрасывает этот бюджет, интервал и защиту от повторных вопросов.

Резерв входит в общий бюджет. Например, при `normal` после четырёх самостоятельных попыток последний вызов доступен только для `confusion`. Эта причина освобождает от ожидания интервала, но расходует бюджет.

Явная просьба пользователя (`user`) разрешена при любой политике, не расходует самостоятельный бюджет и не требует ожидания. Защита от повторного пакета с уже полученным ответом действует и для неё. Две подряд ошибки провайдера блокируют дальнейшие обращения в той же сессии.

Настройки задайте перед запуском Qwen:

```sh
export SENIOR_POLICY=normal
export SENIOR_MAX_CONSULTATIONS=5
export SENIOR_CONFUSION_RESERVE=1
export SENIOR_MIN_INTERVAL_SECONDS=60
qwen
```

Политику можно также хранить в `.senior-advisor/policy.json`. Параметры CLI имеют приоритет над переменными окружения, а переменные — над файлом. Агент может менять файл политики только по явной просьбе пользователя. Все настройки описаны в [configuration.md](senior-advisor/references/configuration.md).

## Провайдеры и настройки

| Значение `SENIOR_PROVIDER` | Подключение |
| --- | --- |
| `codex` | Установленный и авторизованный Codex CLI |
| `claude` | Установленный и авторизованный Claude Code |
| `grok` | Установленный и авторизованный Grok CLI |
| `kimi` | Установленный и авторизованный Kimi Code |
| `zai` | HTTP API, ключ в `ZAI_API_KEY` |

По умолчанию используется `auto`: первый доступный провайдер в порядке `codex,claude,grok,kimi,zai`. Доступность определяется так же, как в `--doctor`. После ошибки запроса автоматического перехода к другому провайдеру нет.

Чтобы выбрать провайдера явно, задайте переменные перед запуском Qwen:

```sh
export SENIOR_PROVIDER=claude
export SENIOR_TIMEOUT_SECONDS=300
qwen
```

Модель можно задать через `SENIOR_<PROVIDER>_MODEL`, например `SENIOR_CLAUDE_MODEL`. При прямом вызове скрипта параметр `--model` имеет приоритет над переменной окружения. Без переопределения CLI использует свою модель по умолчанию.

Команды установки, авторизация, настройка моделей и отдельного окружения для Codex описаны в [справочнике провайдеров](senior-advisor/references/providers.md). Политика и выбор провайдера настраиваются независимо.

## Формат вопроса и локальная проверка

Обычно пакет составляет сам Qwen. Проверить формат вручную можно без обращения к модели:

```sh
python3 senior-advisor/scripts/ask_senior.py --lint <<'PACKET'
Question: How should push isolate default lists while preserving explicit-list mutation?
Stack: Python 3.12.1, standard library
Given: push(item, bucket=[]) appends item and returns bucket; default calls share a list.
Constraints: Preserve mutation and identity of an explicitly supplied list.
Ruled out: none
Evidence:
def push(item, bucket=[]):
    bucket.append(item)
    return bucket
PACKET
```

Для совета обязательны все шесть заголовков. Лимиты: 1200 байт до `Evidence:`, 100 строк для секции `Evidence:` вместе с заголовком и 8192 байта на весь пакет. `--lint` возвращает JSON с результатом проверки; код выхода `0` означает успех, `2` — ошибку.

Для плана используйте `--kind plan` и другой набор заголовков:

```sh
python3 senior-advisor/scripts/ask_senior.py --kind plan --lint <<'PACKET'
Objective: Перевести запись и обработку заданий с таблицы A на B без потерь.
Stack: CPython 3.12.1; psycopg 3.1.18; PostgreSQL 16.2; Linux 6.8 x86_64
Given: A: id UUID PRIMARY KEY, payload jsonb; B пуста, схема совпадает; 1 процесс записи, 4 обработчика; тесты повторной обработки проходят.
Constraints: Пауза записи до 30 с; потеря заданий недопустима.
Unknowns: Скорость копирования; способ учёта записей при переключении.
Done when: Запись и 4 обработчика используют B; сверка UUID не выявляет потерь; тесты повторов проходят; замер паузы до 30 с; откат проверен на копии.
PACKET
```

Пакет плана ограничен 1600 байтами. `Objective:` описывает результат и не заканчивается вопросительным знаком; `Done when:` содержит проверяемые критерии завершения. Вид пакета также определяется автоматически по первому заголовку.

Для реального обращения обязателен `--trigger`. Например, если пользователь сейчас запросил план и подготовленный пакет сохранён в `plan.txt`:

```sh
python3 senior-advisor/scripts/ask_senior.py --kind plan --trigger user --json < plan.txt
```

Этот вызов обращается к внешнему провайдеру. Успешная локальная проверка пакета ещё не означает, что политика разрешит консультацию.

Подробные правила находятся в [SKILL.md](senior-advisor/SKILL.md), примеры сокращения вопросов — в [packet-examples.md](senior-advisor/references/packet-examples.md).

## Журнал и оставшийся бюджет

Из рабочего проекта выполните:

```sh
python3 ~/.qwen/skills/senior-advisor/scripts/ask_senior.py --status
```

Команда показывает действующую политику, историю, отказы, время ожидания и остаток вызовов. Она не обращается к провайдеру и не создаёт сессию на диске. В `remaining` поле `general` показывает доступные обычные обращения, а `confusion` включает их и резерв; складывать эти числа нельзя.

По умолчанию записи находятся в `.senior-advisor/<session>/` относительно текущей рабочей директории:

- `ledger.md` содержит полные пакеты `Q<n>` и ответы `A<n>` либо сообщения об ошибках.
- `ledger.jsonl` хранит метаданные попыток для учёта бюджета и проверки повторов.
- `session.json` хранит сведения о сессии и счётчик отказов политики.

Путь можно задать через `SENIOR_LOG_DIR`. Используйте абсолютный путь, если несколько рабочих директорий должны разделять историю и бюджет. При отказе политики скрипт возвращает код `4` с причиной; агенту запрещено обходить его сменой причины, сессии или увеличением лимита. Учёт зависит от записанного журнала: его нужно сохранять включённым и сообщать пользователю об ошибках записи.

## Передача данных и статус проверки

Подготовленный пакет отправляется внешнему провайдеру и расходует его квоту или оплачивается по условиям вашего аккаунта. Перед отправкой нужно убрать секреты, персональные данные и внутренние адреса: автоматическая проверка по шаблонам не гарантирует обнаружение всех чувствительных данных. Агенту запрещено обходить проверки через `--allow-sensitive`, `--allow-narrative` или `--allow-repeat`.

Журнал содержит исходный текст пакетов и ответы. Добавьте `.senior-advisor/` или выбранную папку журналов в `.gitignore` рабочего проекта. В этом репозитории такое исключение уже есть. Журнал предназначен для пользователя; агент не должен редактировать или удалять его.

По зафиксированным в репозитории проверкам от 8 сентября 2026 года, консультации через Codex и Claude Code прошли полный цикл на macOS. Адаптеры Grok, Kimi и Z.AI реализованы, но полный цикл для них не проверен.

## Обновление

Из директории клона выполните:

```sh
git pull --ff-only
cp -R senior-advisor/. ~/.qwen/skills/senior-advisor/
```

Установленный скилл — отдельная копия. Сам по себе `git pull` её не обновляет; повторное копирование перезапишет локальные правки в совпадающих файлах.

## Разработка

```text
senior-advisor/
├── SKILL.md                     # Инструкции для Qwen
├── scripts/
│   ├── ask_senior.py             # Проверка пакетов и вызовы провайдеров
│   └── test_ask_senior.py        # Офлайн-тесты
└── references/
    ├── configuration.md         # Политики, бюджеты и журнал консультаций
    ├── providers.md             # Подключение провайдеров
    └── packet-examples.md       # Примеры подготовки вопросов
```

Запуск тестов из корня репозитория:

```sh
python3 -B -m unittest discover -s senior-advisor/scripts -p 'test_*.py'
```

Тесты используют стандартный `unittest`, изолируют переменные окружения и блокируют реальные сетевые запросы и запуск CLI провайдеров. Они проверяют валидацию пакетов, выбор моделей, учёт бюджета между сессиями, резерв для `confusion` и запись отказов. Правила для участников — в [AGENTS.md](AGENTS.md).
